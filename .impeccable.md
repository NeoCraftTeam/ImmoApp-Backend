# Design Context — KeyHome

Source de vérité pour le skill `frontend-design`. À éditer si la direction
change ; les futures sessions itéreront depuis ce fichier.

## Marché & audience

- **Géographie** : Cameroun en premier, Afrique francophone ensuite
  (Sénégal, Côte d'Ivoire, RDC…).
- **Langue** : français par défaut.
- **Monnaie** : FCFA (XAF).
- **Réseau** : 4G/3G capricieuse — l'app doit feel rapide même offline.
- **Devices** : majorité Android entry-mid range, iPhone en croissance
  côté bailleurs urbains.

## Les deux apps

### 1. `mobile/visitors` — chercheurs de logement

- **Audience** : 22–40 ans, urbains, étudiants + jeunes pros + diaspora
  qui rentre. Mobile-first absolu, peu de patience pour les UI molles.
- **Jobs to be done** :
  - Découvrir des annonces qui correspondent à leur quartier/budget
  - Comparer 2-3 biens visuellement (photos + prix + équipements)
  - Réserver une visite sans appeler 10 fois
  - Contacter l'annonceur en chat (pas en email)
- **Brand personality** : **« Magazine immobilier africain moderne »**.
  - Éditorial : les photos prennent toute la place, la typo est
    expressive, la mise en page asymétrique.
  - Énergique mais pas criard : le crimson `#F6475F` est dominant
    seulement sur les CTA et les favoris ; le reste respire en
    neutres tintés warm.
  - Différenciation : on n'a jamais l'air d'un "real estate app
    generic" — chaque écran a une voix.
- **Anti-AI-slop strict** :
  - Pas de "icône rondie + heading + paragraphe" répété en grille
  - Pas de hero "metric XL + petit label + sparkline"
  - Pas de glassmorphism gratuit, pas de gradient sur les chiffres
  - Pas de centered text full-page — préférer l'asymétrie
  - Empty states qui apprennent l'interface, pas "rien ici"
- **Référence d'esprit** : Airbnb (mais plus chaud) × Vogue
  (mais mobile) × Apple Maps (clarté de l'info).

### 2. `mobile/owners` — bailleurs et agences

- **Audience** : 30–55 ans, propriétaires (1-3 biens) + petites agences
  (5-30 biens). Souvent moins tech-savvy que les visiteurs ; ont
  besoin de confiance, pas de fun. Beaucoup utilisent un seul device
  pour leurs comptes business.
- **Jobs to be done** :
  - Publier une annonce sans se perdre dans un formulaire de 30 champs
  - Voir d'un coup d'œil "qui veut visiter quoi" et "combien j'ai gagné ce mois"
  - Gérer locataires + baux + paiements sans Excel
  - Booster une annonce qui ne décolle pas
- **Brand personality** : **« Dashboard pro qui ne fait pas peur »**.
  - Minimaliste raffiné : teal `#0D9488` dominant en accents, neutres
    tintés cool pour le background.
  - Typo qui inspire confiance pour les chiffres (tabular nums,
    alignement strict des montants).
  - Beaucoup de respiration : moins de cards, plus de séparateurs
    fins ou simplement de l'espace.
  - Différenciation : ressemble plus à Linear/Stripe/Notion qu'à
    un "CRM immobilier" génerique.
- **Anti-AI-slop strict** :
  - Pas de grille de 4 stat cards identiques avec icône + label + chiffre
  - Pas de glassmorphism sur le dashboard
  - Pas de "Pro" dans l'UI (déjà retiré) — c'est **KeyHome Owner**
  - Pas de gradient sur les KPI
  - Pas de "rounded icon above every heading"
- **Référence d'esprit** : Linear (sobriété nerveuse) × Stripe (typo
  pour chiffres) × Notion (densité d'info maîtrisée).

## Tokens partagés

- **Tinted neutrals** : tous les gris ont une teinte du brand (warm
  pour visitor, cool pour owner). Pas de `#000` ni `#FFF` purs.
- **Type scale** modulaire 1.250 (Major Third) sur les deux apps.
- **Spacing rhythm** varié : `4 / 6 / 8 / 12 / 16 / 24 / 40 / 64`
  — JAMAIS le même padding partout.
- **Motion** : ease-out-quart par défaut, durée 240–380 ms. Pas de
  bounce / elastic. Native driver obligatoire (RN Animated).
- **Empty states** : illustration ou icône custom (pas Lucide nu) +
  copy qui apprend, + CTA primaire.
- **Loading** : skeletons matchant la géométrie cible, jamais de
  spinner centered full-screen sauf cold-start.

## Hors-périmètre

- Pas de dark-mode mandatory (les 2 apps supportent l'auto-switch via
  Tamagui mais on optimise d'abord le light).
- Pas de support iPad / web — mobile portrait first.
- Pas de RTL (français = LTR).
